# 二、旧方案实际怎么做

设原图是 A，贴入的另一张图是 B，融合结果是 C。

C 的一部分像素来自 A，另一部分来自 B。

## 1. SAM 融合

先根据 A 的 SAM 区域编号，选择部分区域保留 A，其余位置填入 B 在相同位置的像素。

注意：

`mask_ratio=0.7` 控制的是替换的 SAM 区域编号数量，不保证 B 恰好占整张图 70% 的像素。

## 2. 旧对比学习 FCL

以原图 A 为锚点：

- 正样本：A 对应的融合图 C。
- 负样本：同一 batch 中其他融合图。

这里必须说准确：

旧代码不是“先把整张特征图全局池化成一个 512 维向量再比较”。

旧代码实际是：

① 原图和融合图都得到 `[b,512,16,16]` 特征图。

② 每个空间格子取出一个 512 维向量，与另一张特征图相同位置比较。

③ 每个位置计算 InfoNCE，最后对空间位置和 batch 求平均。

因此，旧方法保留了空间位置，但没有根据 A/B 来源区分这些位置。

## 3. 旧方案存在的来源问题

其他融合图可能包含当前原图 A 贴进去的内容。

但是旧 FCL 仍然把这些融合图整体当成负样本，没有排除其中的 A 来源内容。

另外，C 中来自 B 的位置，也没有单独建立“对齐原图 B 对应区域”的正样本关系。

## 4. 旧 SKD 分割监督

融合图 C 输入网络，预测结果与原图 A 的 SAM 标签计算全图 Dice loss。

包括被 B 替换的位置，也仍然按 A 的标签监督。

这是原有代码的实际行为。

## 5. 旧重建

融合图 C 输入网络，重建完整原图 A：

`IFR＝MSE(tanh(重建输出), 原图A)`。

# 三、新方案的完整实现

## 1. 先记录融合图每个位置来自谁

融合时生成来源掩码 M：

- `M=0`：该位置保留的是 A。
- `M=1`：该位置填入的是 B。

像素级形状：

```text
M：[b,1,256,256]
```

融合可以理解为：

`C＝(1-M)×A＋M×B`。

这里的 M 是由实际融合过程得到的来源掩码，不是直接把 SAM 的区域编号当权重。

## 2. 图片经过 Encoder，掩码不经过 Encoder

原图和融合图分别经过同一个二维 U-Net Encoder：

```text
原图特征：[b,512,16,16]
融合特征：[b,512,16,16]
```

来源掩码只做面积下采样：

```text
[b,1,256,256] → [b,1,16,16]
```

得到潜在空间权重 m。

- B 权重是 `m`。
- A 权重是 `1-m`。

m 可以是 0～1 之间的小数。例如某个格子为 0.75，表示这个格子覆盖的原始像素中，约 75% 来自 B。

不是把 0/1 掩码当图片输入 Encoder。

## 3. 用掩码加权平均池化

对融合特征分别提取 A、B 区域。

每个通道的计算是：

`区域特征＝Σ(空间特征×区域权重) ÷ Σ区域权重`。

池化前后维度：

```text
融合特征：[b,512,16,16]
        ↓ 掩码加权平均池化
区域向量：[b,2,512]
```

其中：

- A 区域向量：`[b,512]`。
- B 区域向量：`[b,512]`。

最后做 L2 归一化，维度不变。

这里是区域加权平均池化，不是最大池化，也不是直接对整张特征图做普通全局平均。

另外，掩码是在空间位置上加权：

同一个格子的权重乘到该格子的全部 512 个通道上，不是把 512 个通道拆成 A 通道、B 通道。

## 4. 原图也按同一掩码提取区域

这是最终版本最重要的决定：

正样本、负样本都使用区域表示，不使用全局表示。

以融合图 C 的 A 区域为例：

- C 用 `1-m` 池化，得到 A 来源区域向量。
- 原图 A 也用这个 `1-m` 池化，得到对应区域正样本。
- 其他原图也用这个 `1-m` 池化，得到对应区域负样本。

B 区域同理，使用 m。

特别注意：

提取原图 B 的正样本时，用的是“当前融合图 C 的 m”，不是 B 在另一张融合图中使用的掩码。

“对应区域”指同一掩码覆盖的空间坐标，不代表不同原图中的区域一定属于同一种器官。

## 5. 新对比学习的正负样本

### A 分支

锚点：C 中来自 A 的区域向量。

- 拉近：原图 A 的对应区域向量。
- 拉远：其他原图按同一掩码提取的区域向量。
- 原图 A、B 都不放进负样本。

### B 分支

锚点：C 中来自 B 的区域向量。

- 拉近：原图 B 的对应区域向量。
- 拉远：其他原图按同一掩码提取的区域向量。
- 同样排除来源 A、B。

候选库使用原图，不再使用其他融合图。

每张候选原图在每个分支的候选库中只出现一次，没有把重复的 A/B 候选库拼在一起。

没有额外强迫同一张融合图中的 A、B 区域互相作为困难负样本。

## 6. 损失内部的维度

以当前 `b=24` 为例：

| 内容 | 维度 |
|---|---|
| 原图、融合图的潜在特征 | `[24,512,16,16]` |
| 融合图 A/B 区域向量 | `[24,2,512]` |
| 每个查询掩码提取全部原图的区域向量 | `[24,2,24,512]` |
| 查询与全部原图区域的 cos | `[24,2,24]` |
| 送入交叉熵的 logits | `[48,24]` |

每个区域查询有：

- 1 个正样本。
- 22 个负样本。
- 另一个来源原图被排除，不参与这个分支的分母。

## 7. A、B 两路损失怎么合并

按融合时 A、B 的实际像素面积比例加权。

例如 B 实际占 60%，则 A、B 两路权重约为 40%、60%。

不是一律各占一半，也不是直接把 `mask_ratio=0.7` 当成 B 的像素占比。

如果某个来源区域为空，该分支不参与损失。

## 8. Encoder 不是固定的

主干 Encoder 正常参与反向传播、更新参数。

- 原图分支参与训练。
- 融合图分支参与训练。
- 两个分支使用同一个 Encoder。
- 没有新增冻结主干、动量 Encoder、投影头或队列。

SAM 负责离线生成掩码，不是这里训练中的 U-Net Encoder。

# 四、新方案的 SKD 与重建

## 1. Decoder 仍接收完整融合特征

最终实现不是：

“把 B 的潜在特征删除后，只把 A 特征送入 Decoder”。

实际是：

“完整融合特征和跳跃连接进入 Decoder，只在计算 SKD 时屏蔽 B 像素”。

这样保留上下文，也不影响完整 A 的重建任务。

## 2. 新 SKD 只监督 A 保留像素

计算方式：

① 分割 logits 先做 softmax。

② 预测概率乘 A 保留掩码。

③ A 的 SAM one-hot 标签也乘同一个保留掩码。

④ 再计算 Dice loss。

因此，Dice 分子、分母都排除了 B 像素。

B 不是被当作背景，而是直接不参与 SKD。

已验证：B 像素位置的分割 logits，其 SKD 梯度为 0；A 像素正常获得监督。

## 3. 重建仍然恢复完整 A

这一部分没有改变：

`IFR＝MSE(tanh(重建输出), 完整原图A)`。

包括被 B 替换的位置，也仍然要求恢复 A。

因此，不能说整个预训练里所有 A/B 来源矛盾都已经消除。此次主要修正的是对比配对和 SKD 监督范围，重建任务仍保留 FDAS 原来的目标。

## 4. 总损失

旧方法：

`L旧＝全图SKD＋完整A重建＋0.5×旧FCL`。

新方法：

`L新＝A保留区域SKD＋完整A重建＋0.5×双来源区域对比损失`。

新对比损失替代旧 FCL，没有把两个对比损失叠加。

# 五、新旧方案最直接的区别

| 项目 | 旧方案 | 新方案 |
|---|---|---|
| 对比表示 | 每个空间格子的特征 | 按来源池化的区域向量 |
| 正样本 | 原 A 特征图与对应融合图 | A 区域对原 A 区域；B 区域对原 B 区域 |
| 负样本 | 其他融合图 | 其他原图的相同掩码区域 |
| 来源排除 | 不排除其他融合图中的同来源内容 | 排除原 A、原 B |
| 区域池化 | 无 | 掩码加权平均池化 |
| SKD | 全图按 A 标签监督 | 只监督保留的 A 像素 |
| 重建 | 完整 A | 不变 |
| Decoder 输入 | 完整融合特征 | 不变 |
| 主干网络结构 | 原二维 U-Net | 不变 |

旧方案不能说完全没有改动。

准确说法是：

旧 FCL、旧全图 SKD、旧重建计算保留了，但为了新旧对照，实验设置统一调整为：

- 融合图使用倒序配对，而不是原来的随机抽取。
- 使用同一份病例级训练／留出划分。
- 两组都训练 20,000 步。
- 丢弃不足一个完整 batch 的末批。

这是“统一实验设置下的新旧方法对照”，不是原始训练设置的逐项复刻。

# 七、已经完成的实验

## 1. 两组都重新训练，没有复用历史旧权重

之前旧的 100,000 步权重，其训练病例清单找不到了。

为了避免留出病例可能已被旧模型见过，用户决定：

旧方法、新方法都重新从头训练。

本轮最终比较使用的是两组新训练的 20,000 步权重。

不是“拿同一个旧 Encoder，换种池化方法算一下”得到的结果。

## 2. 数据划分

按切片文件名中 `_slice` 前面的病例标识归组，然后划分。

| 数据 | 病例标识数量 | 切片数量 |
|---|---:|---:|
| 完整预处理清单 | 2300 | 417,965 |
| 预训练集 | 1840 | 330,314 |
| 留出集 | 460 | 87,651 |

两组使用完全相同的训练清单。

最终从留出集固定抽取：

- 9600 张切片。
- 覆盖 459 个病例标识。

训练与留出病例标识无重叠。

## 3. 训练设置

- `batch_size=24`。
- 输入 `256×256`。
- 两组各训练 20,000 iteration。
- 初始学习率 `0.01`。
- Adam 优化器。
- 多项式学习率衰减。
- 对比温度 `0.1`。
- 对比损失系数 `0.5`。
- 随机种子 `1337`。
- 每 5000 步保存权重。
- 未启用 AMP 混合精度训练。

## 4. 公平评估方式

每个评估 batch 只生成一次融合图和掩码，新旧模型看到完全相同的：

- 原图。
- 融合图。
- 来源掩码。
- 正样本索引。
- 负样本候选。

“其他图平均 cos”指同一个 batch 内，排除 A、B 后的 22 张原图。

不是与全部 9600 张图两两比较，也不是与其他融合图比较。

# 八、最终相似度结果

定义：

`相似度差＝正样本cos－其他图平均cos`。

## 1. 主要结果：区域对区域

| 内容 | 方法 | 正样本 cos | 其他图平均 cos | 差值 |
|---|---|---:|---:|---:|
| A 区域对原 A 对应区域 | 旧方法 | 0.8730 | 0.7615 | 0.1115 |
| A 区域对原 A 对应区域 | 新方法 | 0.8547 | 0.0397 | 0.8151 |
| B 区域对原 B 对应区域 | 旧方法 | 0.8954 | 0.8436 | 0.0518 |
| B 区域对原 B 对应区域 | 新方法 | 0.9021 | 0.0233 | 0.8788 |

A 区域差值增加约 `0.7036`，B 区域差值增加约 `0.8270`。

大白话：

旧方法与自身来源很像，但与其他图也很像。

新方法基本保持与自身来源的相似度，同时显著降低了与其他图的相似度。

本轮观察到的主要改善是“来源区分更明显”，不是正样本 cos 全面大幅提高。

## 2. 辅助结果

| 内容 | 方法 | 正样本 cos | 其他图平均 cos | 差值 |
|---|---|---:|---:|---:|
| 融合全图对原 A 全图 | 旧方法 | 0.9214 | 0.8586 | 0.0628 |
| 融合全图对原 A 全图 | 新方法 | 0.3076 | 0.0091 | 0.2985 |
| A 区域对原 A 全图 | 旧方法 | 0.8215 | 0.7530 | 0.0685 |
| A 区域对原 A 全图 | 新方法 | 0.4656 | 0.0034 | 0.4622 |
| B 区域对原 B 全图 | 旧方法 | 0.8892 | 0.8416 | 0.0476 |
| B 区域对原 B 全图 | 新方法 | 0.7740 | 0.0078 | 0.7662 |

这些全图、区域对全图指标只是辅助评估。

新方法实际训练仍然是区域对区域，不能因为结果文件中存在这些指标，就误认为训练里混入了全局对比。

## 3. 怎么理解结果

目前支持的结论：

- 新方案在这批留出数据上的区域来源区分明显增强。
- 正样本区域相似度基本维持。
- 全图与 A 的相似度下降，不是所有指标都上升。

目前还没有的结果：

- 新旧权重的下游分割 Dice 对照。
- 单独拆分“区域对比”和“A 区域 SKD”的贡献。

这次比较的是整套新方案，不能把改善全部归因于其中一个模块。

预训练日志里的 `Dice` 字段实际记录的是 Dice loss，不是下游分割成绩。

# 十二、FLARE 实际预处理：没有使用那份 nnUNetPlans

这是最后讨论中新增的重要信息。

当前流程是：

原始 CT → 逐切片 min-max → 缩放到 `256×256` → 转 uint8 → SAM 生成掩码 → 图像映射到 `[-1,1]` → 保存 H5 → 预训练读取。

相关代码：

- [generate_masks.py](/mnt/e/PeiweiWu/SSL/FDAS-modified/generate_masks.py:90)
- [pre_process.py](/mnt/e/PeiweiWu/SSL/FDAS-modified/pre_process.py:90)
- [预训练数据读取](/mnt/e/PeiweiWu/SSL/FDAS-modified/utils/dataloader.py:98)

与用户贴出的 nnUNetPlans 对照：

| 项目 | nnUNetPlans | 当前流程 |
|---|---|---|
| XY spacing | `0.77832 mm` | 不按物理 spacing 重采样 |
| HU 截断 | `[-928,692]` | 未使用 |
| 固定均值、标准差 | 约 `-3.3483、173.1993` | 未使用 |
| 强度处理 | CTNormalization | min-max、uint8、映射到 `[-1,1]` |
| 二维输入 | `640×640` | `256×256` |
| 二维 batch | 8 | 24 |
| 网络 | 8 层级、InstanceNorm | 5 层级、BatchNorm |
| 三维配置 | 包含 3D 方案 | 未使用 |

抽查的 5 个实际训练 H5，尺寸、范围和数值离散特征均与当前流程一致。

新旧方案使用的是同一套预处理 H5，不是新方案单独遗漏了 nnUNet 规则。

如果以后要改成 HU 截断、固定 CT 标准化或 spacing 重采样，需要重新处理原始 CT，不能只改训练配置，也不能从已经 uint8 化的 H5 精确恢复原始 HU。

# 十三、关于“语义”的最终表述

这套方法明确引入的是来源信息：

“这部分来自 A，那部分来自 B。”

它不等于直接赋予器官标签：

“这是肝，这是胰腺。”

SAM 标签目前主要是区域划分编号，不是稳定的器官类别编号。

另外，来源掩码是在空间位置上加权。由于卷积感受野会混合邻域信息，不能说某个 B 位置的 512 维特征已经完全不含 A 的上下文。

因此，合适的表述是：

“利用 SAM 融合来源信息，建立区域级对应关系，减少已知来源带来的错误负样本关系，并使 SKD 监督与保留的 A 像素一致。”

不应直接说：

- 消除了所有假负样本。
- 完全解耦了 A/B 的器官语义。
- 已经证明下游分割更好。
- 一定是第一个做 SAM 融合区域对比的方法。

目前没有完成足以支持“第一个”的系统查新。
